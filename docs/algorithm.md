# 选择规则分析与实现约定

## 原始规则中的冲突和空白

1. **两项时不能同时要求每周各最多两次。** 五个工作日需要五次结果，而 `2 × 2 = 4`，因此两项时仅应用连续工作日上限；大于两项才应用自然工作周上限。
2. **超过五项时，严格排除上周结果可能无解。** 例如六项，上周选了五种，本周只有一种未选；该项本周最多用两次，剩余三天必须回补上周选项。“尽可能”适合作为偏好，在硬性上限之后应用。
3. **权重和频率上限不能同时精确满足。** 三项中某项配置 80%，但每周最多出现两次，连续使用五个工作日时实际频率最多 40%。因此采用“先筛选、再在候选集中按权重抽样”。三项时，每个选项一周至少一次，最多两次；高权重表达偏好，不承诺最终频率。
4. **超过五项时，完整轮换也会影响权重。** 在一个覆盖所有当前选项的轮换周期中，权重主要影响被选中的先后，而不是让高权重项跳过尚未轮到的项反复出现。这是“直到轮空”带来的取舍。
5. **零权重可能与硬性规则冲突。** 如三项中只有一项为正权重，该项本周出现两次后，继续按权重就没有可选项。当前选择要求每项严格为正；想禁用一个选项可删除它，历史仍保留。
6. **必须约定重选如何计数。** 若三次尝试都算入一周，周一就可能耗尽某些选项次数。实现按每天最终结果统计；首次选择免费，另有三次重选，取消确认不计数。
7. **本地文件无法保证不被其所有者修改。** SQLite 比 `.ini` 不易被误改，并提供约束和事务，但不是加密或防篡改方案；同样不防止人为修改系统日期。

## 候选筛选优先级

1. 无选项时报错；一项时直接返回唯一项。
2. 周一至周五应用对应数量的硬性限制。重选查询仅使用当天之前的最终历史。
3. 选项大于五项时，优先选择当前轮换周期内尚未选中的项。优先集为空时回退到符合硬性规则的候选。
4. 在上述候选中，尽量避开**上一自然工作周**出现过的项；全部都是上周项时允许回补。不是任意最近五条记录。
5. 重选时，若剩余候选中有不同于当前结果的项，排除当前项；否则允许结果相同。
6. 对最终候选按当前权重进行随机抽样。若候选权重为 `w₁…wₖ`，选中第 i 项的条件概率为 `wᵢ / Σw`。

例如六项，上周最终结果为 A、B、C、D、E，本周一会优先 F；完成本轮后下一轮开始，仍尽量避开上周项，所以周二可再次选择 F。周三 F 达到周上限，会从 A～E 回补。任何重选都不能绕过周上限。

轮换根据历史最终结果重建：按日期遍历工作日记录，只统计当前仍存在的选项 ID；每当覆盖全部当前选项，就清空已轮到集合，开始下一轮。新增项会优先补入覆盖，删除项不再阻塞轮换。这样无须持久化另一套可能因重选而失步的轮换计数。

## 日期语义

- 使用带时区的本机当前时间戳保存 `chosen_at`，使用对应本机日期作为每天记录的唯一键。
- 工作周为周一至周五；不同年份的同一周也通过“该周周一日期”识别。
- 两项时，周五与下周一视为相邻工作日；若中间任何应有工作日没有选择记录，连续计数中断。
- 周末选择独立按权重抽样，可以重选、保存和查看日历，但不加入工作日计数或轮换。
- 当天修改选项或权重不自动重新抽样。删除了当日选中项也保留当日结果，后续重选仅从现有选项中抽样。
- 程序 30 秒检查一次日期变化，点击选择时再次检查；确认弹窗跨午夜时先刷新到新日期，由用户重新点击。
- 规则按选择时的当前选项数应用。后续增删清单不会追溯修改已经保存的历史。

## 权重维护

采用正浮点数，归一化时先缩放再求和，避免大数相加溢出。不用界面显示的四舍五入结果写回数据库。总和在浮点机器精度内为 1。

- 首次 N 项：各为 `1/N`。
- 批量新增 K 项：令 `M=N+K`；旧权重 `wᵢ′=wᵢ·N/M`，每个新项 `1/M`。旧项总和为 `N/M`，新项总和为 `K/M`。
- 批量删除：剩余项 `wᵢ′=wᵢ/Σ剩余权重`，相对比例不变。
- 修改单项到 t：该项为 t，其余项按旧比例分配 `1−t`。
- 删除全部项：当前清单为空，历史仍保留；重新录入时均等分配。

新增三项一次提交与逐次新增三次的结果可能不同：一次提交时三项各为 `1/M`；逐次提交每次都按新数量重新分配。应用明确按一次提交视为一批。

## 一致性与可维护性

每次增删、改权重、抽样和更新每日次数都在 `BEGIN IMMEDIATE` 事务中完成，失败回滚。SQLite 锁会串行化多个实例对同一数据文件的写入，避免同时重选绕过三次上限。重启后的首次点击不会创建第二条同日记录。

选项软删除，日记录保存选项 ID、名称和颜色快照；重新录入同名项获得新 ID，不会改写过去的日历。正常运行不覆盖或重建不兼容的数据库版本。

目前规则采用带限制的加权抽样，适合个人午餐选择。若未来希望“长期频率尽量接近权重”成为更高优先级，可改为记录期望次数与实际次数的差额进行补偿；仍需限制不可能实现的权重，并明确其与完整轮换之间的优先级。
